# 小花园成长计划 · 需求说明书

Oct 11, 2026 · @Ryan

## 1. 项目概述

这是一个在 iPad 上运行的离线网页小游戏。孩子完成每天的学习和生活任务获得奖励，再用奖励经营一座属于自己的花园（室外花园加室内小屋）。数据只存在 iPad 本地，代码托管在 GitHub、通过 GitHub Pages 发布，由 Claude Code 实现。

### 1.1 目标

1. 把每日任务（学习、喝水、运动、作息、自理）变成可记录、可奖励的打卡。
2. 给奖励一个看得见的去处：种下的花会长大，攒下的金币能换家具。
3. 给家长一个低负担的入口：每晚集中确认一次，能看到各项任务和运动数据的趋势。

### 1.2 用户与使用场景

| 角色 | 设备 | 主要操作 | 时段与时长 |
| --- | --- | --- | --- |
| 孩子（一年级，7 岁，拼音和 100 以内加减法已掌握，喜欢画画和唱歌） | 家里的 iPad，横屏为主 | 看今日任务、报告完成、浇水种花、逛商店、摆放家具 | 放学后到睡前，每次约 5–15 分钟 |
| 家长 | 同一台 iPad，用 PIN 进入家长模式 | 确认任务、录入运动数据、调整任务和目标、备份数据 | 晚上睡前集中处理一次 |

### 1.3 范围

包含：任务打卡与奖励、花园养成游戏（室外和室内）、家长模式、本地存储与备份、PWA 离线运行、GitHub Pages 发布。

非目标（v1 不做）：账号登录、云同步或多设备同步、服务器后端、排行榜与社交、广告与内购、推送通知、金币兑换现实奖励。

### 1.4 关键假设

- v1 只服务一个孩子；数据模型预留 childId，以后弟弟可以接入。
- 只有一台 iPad 使用；换设备靠备份文件迁移。
- 界面为简体中文，任务和按钮都配图标，不依赖长句说明。
- 仓库公开，代码、配置和文档里不写孩子的真实姓名和学校；名字在首次启动时输入，只存在本地。

### 1.5 优先级约定

- P0：v1 必须有，缺了不能上线。
- P1：v1 应该有，可在 P0 完成后补上。
- P2：后续版本。

## 2. 设计原则

以下八条是底线。任何功能和它们冲突时，以原则为准。

1. **只加不扣。** 任务只发奖励、不扣分。家长可以撤销误操作，但没有惩罚性扣分功能。
2. **植物不会死。** 没浇水只会暂停生长、显示口渴，浇水后恢复，不制造损失焦虑。
3. **断签不清零。** 主要成就按“累计天数”计算。连续打卡只是额外的小奖励，断一天不会清空任何已获得的东西。
4. **游戏时长自然有限。** 植物按真实天数生长，水滴只能从现实任务获得，游戏内没有可以无限刷的玩法。每天玩 5–15 分钟就做完了。
5. **奖励对准需要动力的事。** 家长新增任务时，界面提示不要把孩子本来就喜欢做的事放进来（过度理由效应：自发的事挂上奖励后，撤掉奖励反而不做了）。
6. **自报重在诚实。** 孩子自报的任务直接生效、分值较低，系统不做“抓漏”设计。
7. **孩子有选择权。** 种什么、摆在哪、先攒钱买什么，都由孩子决定。家长模式不能替孩子摆放花园，也不能直接塞物品给她。
8. **离线且私密。** 不联网、不收集数据、不接任何第三方统计或广告。

## 3. 功能总览

系统的核心是一个循环：完成现实任务 → 获得金币和水滴 → 用水滴浇花、植物长大 → 收获得金币并点亮图鉴 → 用金币买种子和家具 → 花园变化吸引新访客、出现新目标 → 继续完成任务。

## 4. 任务与奖励系统

每项任务有三种确认方式（家长确认、孩子自报、数值录入），完成后发放金币和水滴。所有数值都在配置文件里，家长可以在家长模式修改。

### 4.3 运动打卡

运动不是必做项。五个子项各自独立，做了几项记几项，不做也不影响全勤。日常练习只奖励“做了”，由孩子自己记录、直接到账；“做了多少”带来的高奖励（刷新纪录）才需要见证。所以虚报数字拿不到额外好处，家长也就不必每次检查，只在孩子主动邀请时参与。

| 子项 | 单位 | 记录方式 | 默认目标 | 动作提示（显示在计时页） |
| --- | --- | --- | --- | --- |
| 跳绳 | 个 / 1 分钟 | 60 秒倒计时后录入个数 | 100 | 无 |
| 坐位体前屈 | 厘米，指尖超过脚尖为正，未到为负 | 直接录入 | 首周测基线后设定 | 家长不要从背后按压 |
| 平板支撑 | 秒 | 正计时，停止即记录 | 30 | 塌腰或撅屁股就停，不硬撑 |
| 悬垂 | 秒 | 正计时，停止即记录 | 首周测基线后设定 | 双手握杠，脚离地 |
| 仰卧起坐 | 个 / 1 分钟 | 60 秒倒计时后录入个数 | 首周测基线后设定 | 双手交叉放胸前，不抱头拉脖子 |

**日常练习：自己做、自己记**

1. 孩子在运动卡片里点开某个子项。
2. 计时类（平板支撑、悬垂）：点“开始”后 app 正计时，她停下时点“停”，秒数自动记录，不用手动输入。
3. 计数类（跳绳、仰卧起坐）：app 60 秒倒计时，开始和结束有语音提示（“开始！”“时间到！”），结束后她输入个数。
4. 体前屈：直接输入厘米数。
5. 记录直接生效，奖励立即到账，不进家长的待确认列表。

计时器的开始和结束提示音要足够响亮，家长在隔壁房间也能听到她在练，不用走过去看。

**破纪录：需要见证**

- 录入的数值超过个人最好成绩时，app 问“要挑战纪录吗？”，并给出两种见证方式：
  - 喊家长来看：家长在旁边点“我看到了”并输入 PIN，当场确认。
  - 录一段视频：把 iPad 立在一旁，用系统相机录下这一次（网页里用带 capture 属性的文件输入调起相机）。视频存在本地，家长有空时在待确认里快进看一眼，确认或驳回。
- 不选见证也可以：这次照常按日常练习记录和奖励，只是不计入个人纪录、不发纪录奖励。
- 视频在家长确认或驳回后自动删除，不进备份。

**奖励**

- 每完成一个子项：+2 金币，立即到账。
- 达到当前目标：再 +1 金币。
- 刷新个人纪录（有见证）：再 +5 金币，并累计一次“刷新纪录”，用于解锁星星树（见 5.7）。
- 当天五项都做了：再 +3 金币、+2 水滴。
- 目标值只由家长手动调整。P2：连续 3 次达标后提示家长可以提高目标。

### 4.4 完成与确认流程

1. 孩子在今日任务页点任务卡片上的“我完成了”。
2. 自报任务：立即发放奖励，卡片显示“已完成”。
3. 家长确认任务：卡片显示“等爸爸妈妈确认”，奖励暂不发放。
4. 家长进入家长模式，在“待确认”列表里一键全部确认或逐项确认。确认后奖励到账，孩子下次打开时看到金币飞入的到账动画。
5. 家长也可以直接勾选孩子没点的任务。
6. 家长可以驳回待确认的任务：不扣分，只是不发放，可附一句话给孩子（如“明天再试试”）。
7. 家长可以撤销一条已完成的记录（误点）：扣回该条奖励，余额最低扣到 0，不出现负数。
8. 补录窗口：今天和前 2 天的记录可以补录、确认或撤销，更早的只读（天数可配置）。

### 4.5 其他奖励规则

- **金币**只在游戏内循环使用，用来在商店买东西，不兑换现实奖励；**水滴**只能从任务获得，用来浇花，不能购买。
- **当日全勤**（当天所有必做任务完成）：+5 金币，日历上点亮一颗星。
- **连续全勤 3 天**：+3 金币。断了不影响任何累计数。
- **累计全勤** 7 / 30 / 100 天：解锁特殊物品（见 5.7）。
- **加分项**：家长随时发放，选一个原因（预设：主动做家务、照顾弟弟、讲一件学校的事、读写坐姿端正，可自定义）和分值（2 / 3 / 5 金币）。孩子端弹出一张小纸条，例如“因为你主动照顾弟弟，获得 3 金币”。
- **日界线**按 iPad 系统时间的 00:00 计算，v1 不提供修改。每条记录归属于它的“任务日”。
- **数值平衡目标**：普通一天约 30–50 金币、约 10 滴水；小件物品当天能买，大件需要攒 1–2 周，练习延迟满足。

## 5. 花园游戏设计

孩子拥有一座室外花园和一间室内小屋。植物靠水滴按真实天数长大，金币用来买种子和家具，好习惯攒够了会解锁特殊植物和小动物访客。

### 5.1 资源

- **金币**：来自任务、收获、出售和访客奖励，用于购买。
- **水滴**：只来自任务，用于浇花。
- **收获物**：鲜花和果实，存在背包里。鲜花可以插进室内花瓶，果实可以卖成金币。

### 5.2 空间

- **室外花园**：网格地图，建议 12 × 8 格。格子分泥土地块（只能种植物）、草地和小路（放装饰）。初始 6 块地（2 × 3），可以用金币扩建，每块 20 金币，最多 24 块。
- **室内小屋**：点花园里的小屋门进入。上方一排墙面格（挂画、窗户、挂钟、镜子），下方 8 × 5 地板格（家具、盆栽、地毯）。墙纸和地板可以更换。
- **池塘**（P1）：作为户外装饰购买后，可以在上面种莲花，并吸引青蛙。
- **温室**（P2）：专门种室内和特殊植物。
- **初始状态**：室外有小屋、6 块空地和一棵装饰小树；室内有一张床、一把椅子和一个空花瓶；赠送 3 颗向日葵种子、2 颗草莓种子和 5 滴水，保证第一天就能种下去。

### 5.3 种植与生长

- 植物分 4 个阶段：种子 → 发芽 → 长大 → 开花或结果。
- 每株植物每天最多浇 1 次水，每次消耗 1 滴水。成熟所需的浇水次数由植物配置决定（见第 6 节），所以生长会跨越几天到十几天。
- 阶段之间的浇水次数按总数平均分配，例如需要 6 次的植物每 2 次升一阶。
- 连续 3 天没浇水：植物显示口渴表情、暂停生长，但不会枯死，浇水后恢复。
- **一次性植物**（大部分花和蔬菜）：收获后地块变空。**多年生植物**（果树、玫瑰）：成熟后保留，之后每浇若干次水再次产出。
- **收获**：点成熟的植物收获，收获物进背包，同时获得该植物的收获金币。第一次收获某种植物时点亮图鉴。
- **铲除**：可以铲掉没成熟的植物，需要二次确认，不退种子。

### 5.4 商店

- 分类标签：种子、户外装饰、室内家具、墙纸地板、特殊（解锁后才出现）。
- 每件物品显示价格。金币不够时购买按钮变灰，并显示“还差 X 金币”，顺便练习减法。
- 未解锁的物品显示锁和解锁条件，例如“累计全勤 7 天”。
- 买到的物品进背包。家具可以按半价卖回，需要二次确认。

### 5.5 摆放与装扮

- 点“装扮”按钮进入编辑模式。可以把背包里的物品拖到格子上，也可以先点物品、再点格子放置。
- 点已摆放的物品弹出浮动菜单：移动、左右翻转、收回背包。
- 物品有占格大小（1 × 1、2 × 1、2 × 2）。拖动时目标格子绿色表示能放、红色表示不能放。
- 摆放规则：植物只能种在泥土地块；户外装饰只能放在草地或小路；室内家具只能放在地板格；挂件只能放在墙面格。
- 撤销上一步（P1）。退出编辑模式时自动保存，没有“保存”按钮。

### 5.6 访客与图鉴

- 花园满足某些条件时（见 6.4），小动物会来访：在花园里走动或停留，点它会播放小动画并说一句话。
- 第一次来访时点亮图鉴，奖励 5 金币。
- 图鉴分三页：植物（种出过的显示彩色，没种过的显示剪影）、访客、成就徽章。

### 5.7 特殊物品与成就

特殊物品把好习惯和花园连起来，全部按累计数解锁，不要求连续。

| 特殊物品 | 类型 | 解锁条件 | 对应习惯 |
| --- | --- | --- | --- |
| 彩虹花 | 植物 | 累计全勤 7 天 | 坚持 |
| 书页花 | 植物 | 阅读类任务（英语阅读加语文阅读）累计 30 次 | 阅读 |
| 音符花 | 植物 | 英语口语课累计 20 节 | 英语 |
| 星星树 | 植物 | 运动刷新个人纪录累计 5 次 | 运动 |
| 水晶莲 | 植物，种在池塘 | 喝水任务累计 20 天 | 喝水 |
| 金色秋千 | 户外装饰 | 累计全勤 30 天 | 坚持 |
| 星星路灯 | 户外装饰 | 累计全勤 100 天 | 坚持 |

成就徽章（P1）示例：第一次收获、种满 6 块地、集齐 10 种植物、迎来第一位访客、小屋摆满 10 件家具、第一次刷新运动纪录。

### 5.8 心愿单

- 孩子可以把商店里的一件物品设为“心愿”。首页显示进度条，例如“已攒 120 / 300 金币”。
- 金币够了时进度条发光提示；买到后播放庆祝动画，心愿单清空，等她挑下一件。

### 5.9 后续玩法（P2）

- **季节与节日**：按真实日期切换北京的四季背景；春节、中秋、六一、生日等出现限定装饰。

### 7.2 任务卡片

- 每张卡片：图标、任务名（20 pt 以上）、奖励（如“5 金币 1 水滴”）、状态。
- 状态只有四种：未开始（中性灰）、等确认（黄色沙漏）、已完成（绿色勾加花瓣动画）、已驳回（灰色，附家长的一句话）。
- 未完成不用红色、不用叉号。

### 7.3 iPad 交互规范

- 目标设备：iPad，iPadOS 17 及以上的 Safari，从主屏幕图标以全屏方式运行。横屏优先，竖屏可用。
- 触控目标不小于 64 × 64 pt，主按钮高度不小于 88 pt。
- 正文不小于 20 pt，任务和按钮都配图标。
- 不把双击或长按作为唯一操作方式；拖拽同时提供“先点物品、再点格子”的替代方式。
- 禁用页面缩放、双指缩放和橡皮筋回弹，适配屏幕安全区域。
- 关键操作有动画反馈：金币飞入、植物升阶、收获、访客出现。每个动画不超过 1.5 秒，点一下可跳过。
- 音效：轻柔短音效，默认开，可在设置里关。v1 不放背景音乐。
- 不可逆操作（铲除、出售、撤销记录、重置数据）一律二次确认。
- 色彩明亮柔和，不出现警告式的文案。
- 首次加载后完全离线可用；从主屏幕冷启动不超过 2 秒。

- 标题、数字、按钮文字：站酷快乐体（ZCOOL KuaiLe，OFL 开源授权），圆润俏皮。
- 正文和任务说明：系统自带的苹方，保证一年级孩子读得清楚。
- 快乐体做子集化，只保留界面里用到的字，随应用打包，离线可用。

**形状与质感**

- 卡片圆角 24 px，按钮做成胶囊形；描边 2–3 px，用同色系深一档的颜色。
- 按钮是果冻质感：底部有一道同色系的深色投影，按下时下沉并轻微缩小。
- 阴影柔和、略带粉色调，不用纯灰黑色阴影。
- 自绘图标和插画统一为粗圆描边、圆润造型。

**场景插画**

- 室外天空按 iPad 系统时间变化：早上淡蓝、下午暖黄、傍晚粉橙、夜里深蓝紫并出现星星；云朵缓慢飘动。
- 草地是浅绿色，点缀小白花；泥土地块是圆角的浅棕色块；小屋是圆润的童话小屋，屋顶用她选的颜色。
- 室内是暖色木地板配默认浅粉墙纸，窗户里能看到当前的天色。
- 所有用 SVG 绘制的东西（种子土堆、发芽阶段、特殊植物、秋千、池塘、吉祥物）都画上豆豆眼和粉色腮红；emoji 保持原样。

**吉祥物**

- 一个原创的小花苞精灵，首次启动时由孩子给它起名。
- 它出现在空状态（如“今天还没种花哦”）、操作提示和庆祝时刻，会眨眼、会蹦跳。
- 不使用任何已有的卡通形象或品牌角色。

**动效与音效**

- 动效偏弹性：按钮按下后回弹；植物升阶时轻轻一跳并冒出小爱心；完成任务时花瓣和星星飘落；金币“叮”地飞进余额栏；访客从画面边缘蹦进来。时长遵守 7.3 的 1.5 秒上限。
- 音效用木琴、铃铛一类的清脆短音，使用原创或 CC0 授权的素材。

## 8. 家长模式

家长每晚花 1–2 分钟完成确认，其他配置偶尔调整。家长模式的首页就是“待确认”列表。

### 8.1 进入与安全

- 点右上角齿轮，输入 4 位 PIN。PIN 只存哈希值（Web Crypto 的 SHA-256 加盐）。
- 连续输错 5 次锁定 1 分钟。
- 忘记 PIN：答对一道两位数乘两位数的乘法题（如 37 × 24，每次随机出题）后可以重设。这对一年级孩子足够。
- 离开家长模式或 2 分钟无操作后自动退出。

### 8.2 功能

| 功能 | 说明 | 优先级 |
| --- | --- | --- |
| 待确认 | 按日期分组；全部确认、逐项确认、驳回（可附一句话）；破纪录视频在这里快进查看 | P0 |
| 今日记录 | 直接勾选任务完成、录入运动数值；补录前 2 天；撤销误操作 | P0 |
| 加分 | 选原因（预设或自定义）和分值（2 / 3 / 5），孩子端弹出小纸条 | P0 |
| 任务配置 | 增删改任务，调整排序、频率、确认方式、奖励、是否必做；必做上限（默认 6） | P0 |
| 运动目标 | 每个子项的目标值和频率；查看历史和个人纪录 | P0 |
| 统计 | 近 7 / 30 天各任务完成率（日历热力图）、运动各子项折线图、金币收支流水 | P1 |
| 数值调整 | 修改物品价格和解锁条件（高级设置） | P1 |
| 数据 | 导出备份、导入备份、显示上次备份时间、重置全部数据（需手动输入“确认重置”） | P0 |
| 设置 | 音效、孩子名字和花园名、修改 PIN、检查新版本 | P0 |

### 8.3 家长不能做的事

为保护孩子的选择权（原则 7），家长模式不提供以下功能：替孩子摆放花园、直接往背包里加物品、直接修改金币余额。家长影响孩子资源的唯一途径是确认任务和发放加分。

## 9. 数据与本地存储

全部数据存在 iPad 浏览器的 IndexedDB 里，没有服务器。防丢的关键是“只从主屏幕打开”加“定期导出备份”。

### 9.1 存储方案

- 用 IndexedDB 存全部数据，通过 Dexie.js 封装。
- 启动时调用 `navigator.storage.persist()` 申请持久化存储。
- 每次操作即时写入，没有“保存”按钮。
- 金币和水滴不存余额，存流水；余额等于流水求和。这样撤销、对账和统计都简单。
- 数据带 `schemaVersion`。升级结构时执行迁移脚本，迁移前先在库里保留一份上一版本的快照。
- 静态配置（任务默认值、物品目录、访客条件、解锁规则、数值平衡）放在代码里，不入库；家长改过的任务和数值才入库。

### 9.2 风险与对策

| 风险 | 对策 |
| --- | --- |
| 在 Safari 标签页里打开和从主屏幕图标打开，是两份互相独立的数据 | 引导页要求先“添加到主屏幕”；检测到不是全屏模式运行时，顶部常驻提醒“请从主屏幕图标打开” |
| 清除 Safari 网站数据，或系统清理存储，会丢数据 | 申请持久化存储；家长模式每 7 天提醒一次导出备份 |
| iPad 丢失、损坏或换新 | 备份文件可以通过系统分享面板存到“文件”、隔空投送，或发给自己；在新设备导入 |
| 改系统时间刷奖励 | 每条记录保存真实创建时间；发现时间倒退时在家长模式提示，不做强制拦截 |

### 9.3 备份格式

- 单个 JSON 文件，文件名 `garden-backup-YYYYMMDD.json`，包含 `schemaVersion`、导出时间和全部表数据。P2 的图片以 base64 内嵌；纪录见证视频不进备份。
- 导出：iPad 上优先用 Web Share API 调起分享面板，不支持时退回为下载文件。
- 导入：先校验格式和版本，显示摘要（备份日期、金币余额、物品数、记录天数），二次确认后覆盖当前数据。

## 10. 技术方案与发布

纯前端静态站点，React 加 TypeScript 构建，做成 PWA，由 GitHub Actions 自动部署到 GitHub Pages。

### 10.1 技术栈

| 用途 | 选型 | 说明 |
| --- | --- | --- |
| 构建 | Vite | 当前稳定版 |
| 界面 | React + TypeScript | 当前稳定版，严格模式 |
| 状态管理 | Zustand | 轻量，适合本地状态 |
| 本地存储 | Dexie.js（IndexedDB） | 见第 9 节 |
| 离线 | vite-plugin-pwa（Workbox） | 预缓存全部静态资源 |
| 场景渲染 | DOM + CSS Grid 绝对定位 | 不引入 Canvas 游戏引擎；网格和摆放用普通元素实现，便于触控和调试 |
| 动画 | CSS 动画为主 | 必要时用轻量动画库 |
| 统计图 | 手写 SVG 或轻量图表库 | 只有折线和日历热力图两种 |
| 测试 | Vitest + Playwright（WebKit，iPad 视口） | 见 10.4 |

### 10.2 代码结构

```
little-garden/
├─ src/
│  ├─ app/            # 路由、布局、首次启动引导
│  ├─ features/
│  │  ├─ tasks/       # 今日任务、运动打卡、计时器
│  │  ├─ garden/      # 室外场景、种植、浇水、收获
│  │  ├─ house/       # 室内场景
│  │  ├─ decorate/    # 装扮编辑：拖拽、点放、占格校验
│  │  ├─ shop/        # 商店、背包、心愿单
│  │  ├─ codex/       # 图鉴、访客、成就
│  │  └─ parent/      # 家长模式
│  ├─ data/           # 静态配置：tasks、exercises、plants、outdoor、indoor、visitors、unlocks、balance
│  ├─ engine/         # 纯函数：奖励计算、任务日、生长、解锁与访客判定
│  ├─ db/             # Dexie 表定义、迁移、备份导入导出
│  └─ ui/             # 通用组件：按钮、卡片、弹窗、余额栏
├─ public/            # 应用图标、manifest
├─ .github/workflows/deploy.yml
└─ docs/SPEC.md       # 本文档
```

- 业务规则全部写成 `engine/` 里的纯函数，不依赖 React 和数据库，方便单元测试。
- 所有可调数值集中在 `data/balance.ts`。

### 10.3 发布

- GitHub 公开仓库，推送到 main 分支后由 GitHub Actions 构建并发布到 GitHub Pages。公开仓库可以免费使用 Pages。
- `vite.config` 的 `base` 设为 `/<仓库名>/`，PWA manifest 的 `start_url` 和 `scope` 与之一致。
- manifest 设置 `display: standalone`、横屏优先、应用名和主屏幕图标；同时提供 `apple-touch-icon` 和 iOS 全屏所需的 meta 标签。
- 更新策略：Service Worker 发现新版本时，只在家长模式里提示“有新版本，点击更新”，不在孩子使用中途强制刷新。
- 隐私：仓库里不出现孩子的真实姓名、学校或照片；示例数据用虚构名字。

### 10.4 测试要求

- 单元测试（Vitest）覆盖：任务日与日界线边界、按频率生成当日任务、奖励与全勤计算、撤销后余额不为负、生长与口渴规则、解锁与访客判定、备份导出再导入后数据一致。
- 端到端冒烟测试（Playwright，WebKit，iPad 横屏视口）：首次引导 → 完成一项自报任务 → 家长确认一项任务 → 买种子 → 种下 → 浇水 → 摆放一件家具 → 刷新后状态保持。
